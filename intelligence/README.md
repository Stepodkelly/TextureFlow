# TextureFlow Intelligence

This package is TextureFlow's advisory intelligence boundary. It performs
deterministic person resolution, attention scoring, bounded context assembly,
summarization, and reply drafting. It cannot create proposals, grant
confirmation, queue commands, execute Android actions, or issue receipts.

## Architecture

```text
NotificationEvent[]
  -> deterministic alias resolution
  -> deterministic priority features
  -> bounded person context (at most 5 events / 2,000 body characters)
  -> untrusted notification wrapper
  -> IntelligencePort
       -> OpenAI Responses API with strict JSON Schema
       -> deterministic adapter when unavailable
  -> local strict validation and deterministic priority post-policy
  -> advisory summary or draft text
```

The package imports the canonical `NotificationEvent` and attention types from
`shared/contracts/domain.ts`. Similar names are never fuzzy-merged. Unknown
senders receive stable provisional IDs, and alias collisions return an explicit
ambiguity.

## Use

```ts
import { createIntelligenceService } from "@textureflow/intelligence";

const intelligence = createIntelligenceService({
  apiKey: process.env.OPENAI_API_KEY,
  model: process.env.OPENAI_MODEL,
});

const summary = await intelligence.summarize({
  events,
  userRequest: "What needs my attention?",
});
```

When no API key is supplied, or the API times out, refuses, returns invalid
JSON, violates the schema, or is unreachable, the result is generated by the
deterministic adapter and reports `source: "DETERMINISTIC_FALLBACK"`. No caller
needs a separate offline code path.

`createIntelligenceService` only constructs an OpenAI adapter when an API key is
explicitly passed. It does not read a dotenv file or any unrelated service
credential. The default model is `gpt-5.6-luna` and can be overridden by the
caller.

## Integration boundary

The Convex owner can instantiate this service inside the lead-owned
`convex/intelligence.ts` and pass canonical notification events into
`summarize` or `draftReply`. The returned data is advisory. Proposal creation
must still occur in the proposal subsystem, and dispatch must still preserve:

```text
proposal -> confirmation -> command -> Android receipt
```

Do not convert a draft directly into a command. Do not treat a model summary as
proof that anything happened.

## Security properties

- Notification strings are serialized under `UNTRUSTED_NOTIFICATION_DATA`.
- The system policy explicitly denies confirmation and execution authority.
- Requests set `store: false` and use Responses API strict structured output.
- Local validators reject missing keys, extra keys, invalid enums, oversized
  strings, and non-finite or out-of-range confidence values.
- Deterministic scoring runs before inference and cannot be silently replaced by
  the model. Model influence is bounded to a small adjustment for inconclusive
  scores.
- Promotional notifications stay local unless a caller explicitly requests
  model use. Context is capped before any network request.

Prompt isolation reduces prompt-injection risk but does not make model output
trusted. The local validator and the absence of any execution interface are the
enforcement boundary.

## Commands

From this directory:

```sh
npm install
npm run check
npm test
```

The eval fixtures live in `../shared/evals/intelligence-cases.json` and cover
malicious content, ambiguous names, urgency, promotions, and cross-application
context.

## Known failure behavior

- Invalid timestamps receive a conservative recency value.
- Unresolved senders receive provisional identities and lower confidence.
- Ambiguous identities do not receive person context.
- A malformed or unavailable model response is never retried automatically;
  the current turn falls back immediately for predictable hackathon latency.
- Deterministic drafts are intentionally generic unless the user supplied exact
  draft text.
